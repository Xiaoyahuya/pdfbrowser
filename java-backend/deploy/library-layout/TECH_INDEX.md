## Go 与 Rust 后端扩展路线

Go 和 Rust 都能构建生产级后端，但解决问题的侧重点不同。先掌握网络、数据库、鉴权、测试和可观测等通用后端能力，再选择语言生态。

### Go 路线

- **适合场景：** 云原生服务、网关、平台工具、高并发网络服务和强调交付效率的团队。
- **学习主线：** 类型与接口 → goroutine/channel/context → net/http → database/sql → 测试、pprof 与部署。
- **核心边界：** 通过显式错误、有限并发、超时取消和背压控制复杂度。

### Rust 路线

- **适合场景：** 强调内存安全、低延迟、资源可预测、系统集成或高可靠基础设施的服务。
- **学习主线：** 所有权/借用/Trait → Future/Pin → Tokio → Axum/Tower → SQLx、tracing 与部署。
- **核心边界：** 用类型系统表达所有权和并发约束，并明确取消安全、unsafe 与 FFI 的责任。

### 如何选择

- 优先快速交付、部署简单和云原生工具链时，通常先学 Go。
- 优先内存安全、性能可预测和系统级控制时，通常选择 Rust。
- 已有 Java/Spring 项目不必为了语言而重写；应依据性能证据、团队能力和生态依赖做增量选择。

### 后端能力验收

- [ ] 能用 Go 实现带超时取消、有限并发、数据库事务、日志指标和优雅停机的 HTTP 服务。
- [ ] 能用 Rust 实现所有权边界清晰、取消安全、可观测并经过测试的 Tokio Web 服务。

## 推荐学习顺序

- **先补齐 Web 基础：** HTML 语义、CSS 布局、JavaScript 模块/异步、HTTP/JSON。
- **用 Vue 做单页应用：** 组件、响应式、路由、状态管理、表单、接口调用。
- **系统学习 Java：** 类型与 OOP → 集合/异常 → Stream → IO → 并发 → JVM。
- **进入 Spring：** IoC/DI → Boot 自动配置 → MVC/REST → 数据与事务 → 安全与测试。
- **最后贯通工程化：** 契约、鉴权、缓存、消息、可观测、容器化、性能与故障处理。

## 贯通项目

**项目建议：** 构建一个“团队任务与知识库”系统：Vue 管理台 + Spring Boot API + 关系数据库 + Redis，可选消息队列。

- **前端：** 登录、路由守卫、任务看板、富表单、分页筛选、全局错误提示、组件与端到端测试。
- **后端：** 分层或模块化单体、参数校验、统一错误、事务、审计、幂等、权限、缓存、异步任务。
- **契约：** OpenAPI 或明确的 DTO；日期、分页、错误码、空值和枚举语义必须一致。
- **运行：** 容器镜像、外部配置、数据库迁移、健康检查、指标、日志关联 ID、优雅停机。
- **验收：** 功能正确之外，还要验证越权、重复提交、并发更新、慢查询、缓存失效和服务重启。
